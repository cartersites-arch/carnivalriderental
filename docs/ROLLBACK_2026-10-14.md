## How to roll back

The Test marketplace, its credentials and its data are untouched by the cutover (nothing was written
to Test; no Test credential was rotated).

1. **Fast path (no live customer activity yet):** Vercel → Deployments → promote
   `dpl_4FGMmY2a2yWRuf8dkh5DC9T74PN2` (instant rollback), then restore the plain variables above
   (`SHARETRIBE_CLIENT_ID`, `SHARETRIBE_MARKETPLACE_URL`, `APP_ENV`, `PUBLIC_INDEXING`). The sensitive
   Test Integration credentials must be re-entered by the founder (Vercel cannot show their old values;
   the cutover replaces them with Live ones). Until then the old deployment can browse but reports
   every operator as uncontactable.
2. **Indexing only:** set `PUBLIC_INDEXING=false` and redeploy: robots returns to `Disallow: /`,
   every response carries `X-Robots-Tag: noindex`, the sitemap empties.
3. **After real Live activity exists**, do not move production back onto Test ids: roll forward
   (fix on Live), or set indexing off and keep the Live catalog. Purchases and unlocks reference Live
   operator ids from that point on.

Live records created by the migration carry `privateData.importExternalId`/`companyId`, so they can
be listed (or removed) exactly: `npm run migrate:live -- verify` reads them all.
